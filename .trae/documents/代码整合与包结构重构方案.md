# 代码整合与包结构重构方案

## Context

fspack 已高度模块化（`config/`、`packaging/`、`slim/`、`templates/` 均已子包化），但顶层仍残留一批扁平文件与跨模块重复实现，导致同功能分散、维护成本上升：

- 目录大小 `_dir_size` 有 3 份签名/实现不一致的副本；原子写 `_atomic_write_text` 埋在 nuitka 私有函数中，5 处该用未用；JSON 缓存"读+校验+损坏删除"模式 4 处逐行同构。
- 6 个 `doctor_*.py` + `cli_doctor.py` 平铺顶层，与已子包化的 `config/`/`packaging/` 风格不一致。
- `analyzer.py`/`analyzer_ast.py`/`analyzer_fingerprint.py` 三件套是同一链路的拆分，却散在顶层。
- installer 平台文件（linux/macos/nsis/zip）间有 5 类可上提到 `base.py` 的重复（subprocess 错误处理、单格式编排、staging 归档、ignore 常量、logger）。

目标：抽取公用工具、合并同类文件、子包化，消除重复与分散，且**不改变任何对外行为契约**。用户确认范围为全部四项，彻底迁移不保留兼容 shim，公用工具落到新建 `fspack/_util` 子包。

## 关键约束（已由测试证据核验）

- **大小格式化契约不可合并**：`test_progress.py:278-290` 断言 `fmt_bytes` 为无空格十进制风格（`"1.0KB"`/`"1.00GB"`），`test_cli_doctor.py:144-147,438-440` 断言 `_format_size` 为带空格二进制（`"1.0 MiB"`）。两套互斥，只做物理去重到 `_util/format.py`，**保留两个函数、不统一输出格式**。
- **三份 `_dir_size` 返回类型不同**（`int` os.walk / `int` scandir优化 / `tuple[int,int]` rglob），只做物理去重为三个命名函数，不合一。
- **monkeypatch 生效原理**：`subprocess`/`shutil` 是模块单例，patch `fspack.<mod>.subprocess.run` 改的是共享对象属性，全局生效。子包化后 facade `__init__.py` 必须 `import subprocess`/`import shutil`（带 `# noqa: F401`）并重绑定全部被 patch 的私有名，且 facade 内 `run_doctor` 等须直接引用 facade 命名空间的名（不用 `tools._check_pip()` 限定调用），否则 patch 失效。
- **子包 facade 范本**：`config/__init__.py`、现 `cli_doctor.py:36-165`（re-export + `__all__` 清单）可直接复刻。

## 分阶段实施（每阶段独立通过 ruff/pyrefly/pytest --cov ≥95% branch）

### P1：新建 `fspack/_util` 子包，收敛跨模块工具（风险最低，打基础）

纯内聚重构：搬迁实现体到 `_util`，调用方经 re-export 保留原导入路径，行为不变。

**新建模块与公开签名**：
- `_util/__init__.py`：facade，re-export 下列全部，`__all__` 完整列出。
- `_util/format.py`：
  - `format_size_bin(size_bytes: int) -> str`（= 现 `doctor_envs._format_size`，MiB 带空格）
  - `format_bytes_dec(n: int) -> str`（= 现 `progress.fmt_bytes`，MB 无空格）
- `_util/fsutil.py`：
  - `walk_dir_size(path: Path) -> int`（= `doctor_envs._dir_size`）
  - `scandir_dir_size(path: Path) -> int` + `scandir_tree(root: Path) -> Iterator[os.DirEntry[str]]`（= `sync._dir_size`/`_scandir_tree`）
  - `dir_size_with_count(path: Path) -> tuple[int, int]`（= `size_report._dir_size`）
  - `atomic_write_text(target: Path, content: str, *, encoding: str = "utf-8") -> None`（= `nuitka/compile._atomic_write_text`）
  - `safe_unlink(path: Path, *, logger: logging.Logger | None = None) -> None`（= `nuitka/compile._safe_unlink`）
- `_util/jsoncache.py`：
  - `load_json_dict(path: Path, *, delete_on_corrupt: bool = True, logger=None) -> dict[str, object] | None`——统一"读取→解析→结构校验→损坏删除/忽略"骨架；`delete_on_corrupt` 区分删除型（wheels/cache、nuitka、doctor_envs）与忽略型（pipeline、doctor_bench）。各调用点保留其类型转换/回写外壳，只抽共同骨架，不过度抽象。

**改动文件**：
- 新建 `_util/` 4 文件。
- `progress.py`：`fmt_bytes` 改为从 `_util.format.format_bytes_dec` 导入并以 `fmt_bytes` re-export。
- `doctor_envs.py`：`_dir_size`/`_format_size` re-export `_util`；内联 JSON 损坏删除（239-256）改调 `_util.jsoncache`。
- `packaging/sync.py`：`_dir_size`/`_scandir_tree` re-export（`pyc.py:18` 导入路径不变）。
- `packaging/size_report.py`：`_dir_size` re-export `dir_size_with_count`。
- `packaging/nuitka/compile.py`：`_atomic_write_text`/`_safe_unlink` 薄封装 re-export；`_load_failed_files`/`_load_hash_index` 复用 `_util.jsoncache` 骨架。
- 5 处裸 `write_text` → `atomic_write_text`：`wheels/cache.py:92`、`pipeline/__init__.py:474`、`pipeline/stages.py:638`、`doctor_bench.py:154`、`sbom.py:149`（改前 grep 确认对应测试未 patch `write_text`；若有则该处保留裸写或调 patch）。
- `packaging/__init__.py:37`：修正 dep_analyzer 注释为"二进制依赖剥离"（现误述为"AST import 收集"）。

**测试**：P1 不改导入路径，既有测试原样通过。新增 `tests/test_util.py` 覆盖 `_util` 公开函数（尤其 `atomic_write_text` 的 OSError 清理分支、`load_json_dict` 损坏删除/忽略分支）。

**风险/回退**：`write_text`→`atomic_write_text` 改变 I/O 语义；每处替换独立可回退（re-export 可逆）。

### P2：installer 二次抽取到 base.py（风险中低）

**新增到 `base.py`**：
- `_DIST_IGNORE = shutil.ignore_patterns("release", *_DIST_INTERMEDIATE_EXCLUDES)`——合并 `linux._LINUX_IGNORE`/`macos._MACOS_IGNORE`/`zip._ZIP_IGNORE`（三处完全相同）。
- `_run_tool(cmd, *, error_hint, cwd=None, produces=None) -> None`——泛化 `macos._run_macos_tool`（75-88 范本），支持可选 `cwd`（nsis makensis）与 `produces` 产物校验（nsis 289-290）。替换 linux/nsis/macos 共 6+ 处内联 try/except。
- `_make_staged_archive(dist_dir, staging, release_dir, base, fmt) -> Path`——抽取 `linux.build_tarball`(95-111) 与 `zip._make_zip`(72-89) 逐行相同流程，`fmt` 取 `"gztar"`/`"zip"`。
- `_single_format_release(...)`——抽取 5 个 `*_release` 编排骨架（own_tracker→`_prepare_dist`→`_check_exe`→`_run_stage`→`console.success`→可选 summary），deb GPG 签名 / macos codesign 作为可选钩子传入。**若骨架难覆盖差异，退化为只抽前四项（收益最大、风险最低），`*_release` 编排暂不合并。**

**subprocess patch 兼容（关键）**：抽取后 subprocess 调用集中在 `base._run_tool`（即 `base.subprocess.run`，同一单例）。base.py 保留 `import subprocess`（已有 line 26），现有三条 patch 路径（facade/linux/macos）全部继续生效。linux/macos/nsis 顶部若不再直接调 subprocess，其 `import subprocess` 须加 `# noqa: F401` 保留，维持 `...linux.subprocess.run`/`...macos.subprocess.run` patch 路径存在，否则 `test_linux_installer.py`/`test_macos_installer.py` 的 7+7 处 patch AttributeError。

**改动文件**：`base.py`（新增）、`linux.py`/`macos.py`/`zip.py`/`nsis.py`（删重复改调 base）、`installer/__init__.py`（按需 re-export `_run_tool` 等）。

**风险/回退**：`_single_format_release` 过度抽象晦涩 → 退化为四项；logger 名变化影响日志断言 → grep 确认；每类抽取独立回退。

### P3：analyzer 子包化（彻底迁移，迁移面小）

**目标结构**（对齐 config/）：
- `analyzer/__init__.py`：facade，re-export 全部现 `fspack.analyzer` 公开 API + 测试用私有名（`_parse_file_worker`/`_interleave_by_size`/`_format_ast_errors`）；调度逻辑（`analyze_dependencies`/`_parse_serial`/`_parse_parallel`/worker）留 `__init__.py`。
- `analyzer/ast_scan.py`（**不可命名 `ast.py`**，会遮蔽标准库）= 现 `analyzer_ast.py`。
- `analyzer/fingerprint.py` = 现 `analyzer_fingerprint.py`。

**关键**：`_parse_file_worker`/`_init_parse_worker` 须定义于 `__init__.py`（或被其直接 import），使 `fspack.analyzer._parse_file_worker` 可解析，保证 ProcessPoolExecutor 跨进程 pickle 成功（与现状一致）。

**外部引用**：config/models.py、config/parsing.py、pyc.py、nuitka/compile.py、pipeline/stages.py 均 `from fspack.analyzer import`，facade 保持后零改动。`test_analyzer.py` 仅从 `fspack.analyzer` 导入（无子模块直接引用），基本零改动。

**不做**：`config/parsing.py` 的 `_has_entry`（644-648，找 FunctionDef/If，非 import）语义与 `collect_imports` 不同且异常处理有别，**标注"待用户复核"，P3 不合并**。

**改动文件**：删除 3 个顶层 analyzer 文件，新建 `analyzer/` 3 文件。

**风险/回退**：worker pickle 失败（函数误移子模块）→ 跑并行用例（`test_analyzer.py:293/309`）；子模块误名 `ast.py` → 强制 `ast_scan.py`；删文件前先 facade 全绿。

### P4：doctor 子包化（风险最高，测试改动最大，最后做，依赖 P1）

**目标结构**（对齐 config/ 与现 cli_doctor facade）：
- `doctor/__init__.py`：facade = 现 `cli_doctor.py` 内容（`run_doctor`/`run_doctor_test`/`run_doctor_bench`/`print_doctor_report` + `run_cache_status`/`run_cache_clean`），re-export 全部子模块符号 + `__all__`。
- `doctor/models.py` = 现 `doctor_models.py`（与 `config/models.py` 结构对称，职责不重叠，独立保留）。
- `doctor/envs.py` = 现 `doctor_envs.py`（P1 后 `_dir_size`/`_format_size`/JSON 处理已改调 `_util`）。
- `doctor/tools.py` = 现 `doctor_tools.py`（含 `import shutil`/`import subprocess`）。
- `doctor/report.py` = 现 `doctor_report.py`。
- `doctor/templates.py` = 现 `doctor_templates.py`（含 `import subprocess`/`import shutil`）。
- `doctor/bench.py` = 现 `doctor_bench.py`。
- `doctor/cache.py`：`run_cache_status`/`run_cache_clean` 及渲染辅助（现 `cli_doctor.py:226-354`，服务 `fsp cache` 而非 doctor），facade re-export。**标注"待用户复核是否独立成顶层模块"。**

**facade 重绑定（核心难点）**：以现 `cli_doctor.py:36-165` 为 checklist 完整复制：
- 模块单例型：facade `import shutil` + `import subprocess`（`# noqa: F401`），使 `fspack.doctor.shutil`/`fspack.doctor.subprocess` 属性存在，patch 全局生效。
- 函数引用型：`from doctor.tools import _check_* / _check_tool_version`、`_dir_size`、`_format_size`、`_check_cache_integrity` 等绑定到 facade globals；`run_doctor` 直接引用 facade 名（不改限定调用）。

**测试迁移**（约 108 处引用，`fspack.cli_doctor.` 61+ 次）：
- `test_cli_doctor.py`：全量 `fspack.cli_doctor` → `fspack.doctor`（patch 字符串 + `from` 导入），重命名为 `test_doctor.py`。
- `cli.py:296-302,323-324`：`from fspack.cli_doctor import` → `from fspack.doctor import`。
- 核对 `test_cli.py` 是否有 `fspack.cli_doctor` 引用。

**改动文件**：删除 7 个顶层 doctor 文件，新建 `doctor/` 8-9 模块；改 cli.py 2 处；重命名/改 `test_cli_doctor.py`。

**风险/回退**：facade 漏 re-export 被 patch 私有名（最高风险）→ 以现 `__all__` 逐一核对，`run_doctor` 保持直接引用 facade 名；`subprocess.Popen` patch（templates）缺 import → facade 显式 import；删 7 文件前先 facade 全绿再删。

## 阶段依赖与排序

`P1(_util 基础)` → `P2(installer，与 P1 无强依赖)` → `P3(analyzer，迁移面小)` → `P4(doctor，依赖 _util，测试改动最大放最后)`。

跨阶段铁律（规避 facade re-export 遗漏）：① 以现有 `__all__` 为 checklist；② facade 内函数直接引用命名空间名，不用限定调用。
